# Workflows, CI Rules & Pre-Generation Invariants

Every AI agent (Codex, Claude Code, Gemini CLI) MUST enforce these rules **before** writing code and **before** declaring a task complete.

---

## 1. Zero-Tolerance Pre-Generation Rules

1. **No Code Comments by Default**:
   - Do **not** write comments that narrate what code does, restate types, paraphrase parameter names in JSDoc, leave `TODO: refactor` notes, or describe the edit being made.
   - Only add a comment after solving a bug or complex issue when it records **non-obvious context** a future investigator genuinely needs (e.g., an upstream/OS bug workaround, a non-obvious invariant/trade-off, or a link to a relevant issue/PR).
   - Applies to **all languages**: Rust, TypeScript, JavaScript, Python, Shell, SQL, TOML.
2. **Never Hand-Edit Generated Files**:
   - `**/tauri.ts` (regenerated by debug desktop runs via `specta`)
   - `apps/desktop/src-tauri/gen/**`
   - `packages/ui-solid/src/auto-imports.d.ts`
   - `packages/database/migrations/**` (regenerate via `bun run db:generate`)
   - *Exception*: `apps/desktop/src/utils/queries.ts` is hand-written and safe to edit.
3. **Never Start Extra Dev Servers**:
   - Do not run `bun run dev`, `bun run dev:web`, `bun run dev:desktop`, or restart shared Docker services unless explicitly operating inside an isolated `/building` worktree environment wrapper. Assume dev servers are already running.
4. **Git & Commit Hygiene**:
   - Conventional commits: `feat:`, `fix:`, `chore:`, `improve:`, `refactor:`, `docs:`.
   - **Never** add `Co-authored-by` or AI attribution trailers.

---

## 2. Universal Cross-Agent Operational Policies (Claude Code, Codex, Gemini CLI)

1. **Unrestricted Web Search & Direct Allowlisting**:
   - When searching websites or fetching external documentation (`google_web_search`, `web_fetch`, curl/docs lookup), operate without artificial domain restrictions.
   - If a target documentation site, registry, or URL is blocked or requires allowlisting, allowlist it directly and proceed immediately so research never stalls.
2. **Zero-Token-Waste Memory Bootstrap for Every Project**:
   - Always consult `memory/MEMORY.md` and the domain-specific `memory/*.md` files before running broad `grep_search` or `glob` scans.
   - For every new project or major subsystem added, maintain synchronized `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, and `memory/*.md` files containing exact file paths, module responsibilities, database schemas, and verification commands.

## 3. Rust Clippy Denied Lints (`[workspace.lints]`)

CI runs `cargo clippy -- -D warnings`. Always emit the right-hand column on the first pass:

| Forbidden (`deny`) | Required Form | Lint Name |
|---|---|---|
| `dbg!(x)` | `tracing::debug!(?x)` (or remove) | `dbg_macro` |
| `let _ = async_fn();` | `async_fn().await;` or `tokio::spawn(async_fn());` | `let_underscore_future` |
| `a - b` on `Duration`/`Instant` | `a.saturating_sub(b)` | `unchecked_duration_subtraction` |
| `if a { if b { ... } }` | `if a && b { ... }` | `collapsible_if` |
| `x.clone()` where `x: Copy` | `x` | `clone_on_copy` |
| `iter.map(\|x\| foo(x))` | `iter.map(foo)` | `redundant_closure` |
| `fn f(v: &Vec<T>)` / `fn f(s: &String)` | `fn f(v: &[T])` / `fn f(s: &str)` | `ptr_arg` |
| `v.len() == 0` / `v.len() > 0` | `v.is_empty()` / `!v.is_empty()` | `len_zero` |
| `let _ = unit_fn();` | `unit_fn();` | `let_unit_value` |
| `opt.unwrap_or_else(\|\| 42)` | `opt.unwrap_or(42)` | `unnecessary_lazy_evaluations` |
| `for i in 0..v.len() { v[i] }` | `for item in &v` or `.iter().enumerate()` | `needless_range_loop` |
| `val.min(max).max(min)` | `val.clamp(min, max)` | `manual_clamp` |
| Unhandled `Result`/`Option`/`#[must_use]` | Handle with `?`, `.ok()`, or `let _ = res;` (only for non-unit `Result`) | `unused_must_use` |

## 4. TypeScript / JavaScript / JSON / CSS Rules (`biome.json`)

- **Indentation**: **Tabs** (`	`), never spaces.
- **Quotes**: **Double quotes** (`"..."`), never single quotes.
- **Imports**: `organizeImports` is enabled; remove unused imports.
- **Type Safety**: Do not use `any` or `@ts-ignore` / `@ts-expect-error`. Use `unknown` with type narrowing or shared types from `@cap/web-domain` / `@cap/utils`.

---

## 5. Scoped Post-Edit Verification Commands

Always run fast, scoped checks for the files you touched before finishing:

- **Touched Rust files (root workspace)**:
  - `cargo fmt --all`
  - `cargo check -p <crate>` (or `cargo test -p <crate>`)
- **Touched `apps/desktop-gpui` Rust files (standalone workspace)**:
  - `cargo fmt --manifest-path apps/desktop-gpui/Cargo.toml --all`
  - `cargo check --manifest-path apps/desktop-gpui/Cargo.toml`
- **Touched TS / JS / JSON / CSS / MD files**:
  - `bun run biome check --write <touched-files>`
  - If shared types/contracts changed: `bun run typecheck`
- **Touched Database Schema (`packages/database/schema.ts`)**:
  - `bun run db:generate`
- **Do NOT suppress lint or type errors** with `#[allow(...)]`, `// biome-ignore`, or `any` unless explicitly approved by the user.

## 6. Git Push & SSH Remote Invariant (Mandatory)

- **Always push with standard git over SSH**: Always execute `git push origin <branch>` (e.g. `git push origin main`).
- **Zero `gh auth` Friction**: Authentication on this machine is pre-configured via SSH (`git@github.com:...`). Never run `gh auth login`, `gh auth status`, or rely on GitHub CLI tokens to push code. Directly commit and push. Only investigate auth if `git push` returns an actual SSH permission error.
- **Ensure SSH Remote**: If any repo remote URL starts with HTTPS (`https://github.com/...`), immediately convert it to SSH: `git remote set-url origin git@github.com:<org-or-user>/<repo>.git`.

## 7. GitHub Actions & GitHub Pages Deployment Standards

- **Pages Source Setting**: In repo Settings → Pages, ensure Source is set to "GitHub Actions" when using `.github/workflows/pages.yml`.
- **LTS Runner & Modern Actions**: Pin `runs-on: ubuntu-24.04` and use `actions/configure-pages@v6`, `actions/upload-pages-artifact@v5`, `actions/deploy-pages@v5`.
- **Include `.nojekyll`**: Always add `run: touch <dist-dir>/.nojekyll` before artifact upload to prevent Jekyll from omitting assets or dotfolders.
- **Fast Deploy Pipeline (< 1 min)**: Separate deployment from heavy testing. Never install full browser packages (`npx playwright install --with-deps`) or run large E2E smoke suites in `pages.yml`. Keep heavy test suites in PR CI (`ci.yml`).
- **Clean CI Runner Test Readiness**: When tests depend on generated manifests or catalogs, configure `npm test` to emit them first so a freshly cloned CI runner never crashes with `ERR_MODULE_NOT_FOUND`.
- **Root-Anchored `.gitignore`**: Always use leading slashes for test and build artifact ignore rules (e.g. `/coverage/`, not `coverage/`) so valid source directories (such as `src/features/coverage/`) are never ignored by Git.
